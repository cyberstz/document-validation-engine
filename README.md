# Document Validation Engine

Validation component for a multi-tenant document processing platform.

## Requirements

- PHP 8.3+
- Composer

## Setup

```bash
composer install
```

## Small background for the reader

At first, I wanted to create Laravel project and just create custom validation rules
in addition to existing validator. Add admin page with impersonating tenants and
creating own rules per tenant. But that would not display OOP much, so decided to 
use only PHP with no prod dependencies.

I wanted to add more folders to differentiate roles of classes, but decided not to do so for 
just one file per folder. Whether project expands, there can be added more folders for 
rule providers, worker classes (document, tenant, etc) and engine itself.

## Running the integration script

```bash
composer demo
```

Demo builds rules from configuration, resolves the rules that apply to a tenant and
validates three documents:
1) Satisfies every rule
2) Violates all rules
3) Tenant with no rules configured

## Running the tests

composer test

## Design reasoning

There are two abstractions:
1) `ValidationRule` - interface for creating new rules
2) `RuleProvider` - interface for the future possible new providers like Database or Config

Validation failures are returned and has `isValid` and `errors()` pair to see the list of 
all validation failures by rule.

`id` and `tenantId` are strings not integers just for this implementation. As we don't have 
database here, let's assume they may be uuids in other implementation.

Document size is measured in bytes, not characters. Cases where one character can be multi-byte
is covered in tests.

`ValidationRule` is easily extendable, we need to register them in `RuleFactory`

## Layout

```
src/
|-- Document.php                            Document object
|-- ValidationRule.php                      Interface for rules
|-- RuleProvider.php                        Interface: whice rules apply to a tenant
|-- Validator.php                           Composer of interfaces, collecting outcome
|-- RuleResult.php                          Outcome of rule
|-- ValidationResult.php                    Outcome of validation run
|-- RuleFactory.php                         Rule registrator
|-- RuleConfiguration.php                   Typisation checker
|-- InMemoryRuleProvider.php                Rule provider to accept array rule list
|-- Rules/
|   |-- MaximumDocumentSize.php
|   |-- RequiredMetadataFields.php
|   |-- ProhibitedWords.php
|-- Exceptions/
    |-- InvalidRuleConfiguration.php
    |-- UnknownRuleType.php
```

## Test coverage, demo file and regex

Test coverage and demo file were written with help of Claude based on existing functionality.
Preg was chosen instead of PHP methods like `str_contains` to have a better lookup of 
words that are forbidden and it covers more edge cases. Regex string inside was also generated by AI.
